2. Build your training dataset and watch it learn

Use A/D or the steering controls and W/S for target speed. Capture the inputs before each action. Split entire driving episodes, never neighbouring frames, and never reuse the same start in both splits. Labels are your commands, not reward scores.

Three kinds of example, three different questions

Training fits the weights. Validation comes from different episodes of the same sampler, so it measures generalisation to similar drives. Stress is a deliberately different distribution (deep recovery starts): it is evaluation only and never used to train or to select a checkpoint. A high stress loss next to a low validation loss shows missing coverage, not overfitting.

5. Remove inputs and retrain

All variants start from scratch with the same architecture, examples, batch schedule and update budget. Inputs are removed during both fitting and driving, not just switched off on a pretrained model.

“No future geometry” removes all previews and explicit curvature. “No heading” removes heading channels and the derived margin, but geometric previews can still encode orientation. “No margin” retains lane/heading information from which margin can be inferred. 6. Training playground: capacity, regularisation and baselines

Change how the model is built and trained, then compare train, validation and stress loss with closed-loop driving over several seeds. Uses your dataset from module 2 (load the starter set first). Every configuration is trained from scratch for each seed.

training lossvalidation lossstress lossshaded: ± one sample SD over seeds

Loss values are the weighted action error on recorded states. Closed-loop success uses the 16 fixed development sections: an exact count per seed, summarised over seeds with a bootstrap interval. Label corruption adds Gaussian noise to the training steering labels only; validation and stress labels stay clean. Training loss is then measured against the noisy labels, so it contains a noise floor, and a network that does not memorise the noise can show validation loss below training loss (a negative gap). With few, clean, near-centreline examples a large network may not overfit at all: try label noise, then compare early stopping and weight decay.

7. Data coverage and DAgger

Where should the training examples come from? Four recipes get the same labelled-state budget per track and the same number of Adam updates. Narrow copies the expert from near-centreline starts; broad copies it from broader starts; staged expert follows DAgger's schedule and start distribution but the expert drives; DAgger lets the learner drive and the expert relabel the states it visits. Differences describe whole recipes. Only the comparison with the staged control isolates who chooses the visited states.

Each dot is one seed (one independently trained network) evaluated on fixed sections: nominal and recovery sections are reported separately because pooling hides which regime a recipe fails. Projected occupancy is the share of states in a cell of (offset, heading error, speed, curvature) holding at least 3 examples from at least 2 distinct episodes. It ignores the road previews and previous steering; it is a diagnostic, not a guarantee. “Reference states” are the states the expert itself drives through on the same sections (independent of the learner); “visited states” are the learner's own, so crashed runs contribute fewer states.

Step-by-step DAgger session

Round 0 collects expert demonstrations and trains. Each round then lets your current network drive while the expert labels every state it visits, adds those labelled states and retrains. Validation here is a fixed set of expert episodes (not the growing buffer), so its curve stays comparable between rounds.

8. Diagnose a failure

Run the selected policy from the selected start while recording what it did and what the expert would have done at the same true state. Then ask where they first part ways, whether the expert could still have recovered from that state, and which inputs the policy relies on.

Forks the recorded drive at evenly spaced times and lets the expert finish from that exact state (steering, drivetrain, clock and exit window preserved). It is a counterfactual about a state; it does not prove which earlier action caused the failure, and the outcomes need not switch only once.

Permutation importance scrambles an input group across examples (the wall margin and steering budget are recomputed from the scrambled base inputs, so examples stay physically consistent) and measures how much the loss rises. Correlated inputs share credit, and the five repeats measure shuffle variability only, not population certainty. Corroborate with the retrained input-removal experiment in module 5.

9. Generalization and evaluation leakage

Training uses the eleven existing training circuits. Three newly generated circuits were withheld from every clean reference model until all weights and validation-based selections were frozen. Legacy holdouts have already been seen in earlier work. The seal is a classroom protocol, not secrecy: this page embeds those circuits, so a blind claim needs a teacher-controlled fresh test pack (below).

Teacher-controlled fresh test pack

Your teacher can generate a pack with tools/make_fresh_pack.py --seed <secret> and hand it out only after you freeze your model. The pack's fingerprint can be announced beforehand. Load it here to evaluate the frozen model once.

Deliberately break the rule, only as a lesson

A separate model clone can train on the very test labels it is scored against. The resulting number is explicitly contaminated and cannot support a generalization claim.

Once you reveal or reuse a test set, retraining is exploratory. Clearing examples does not erase test exposure.

10. Robustness and distribution shift

Keep the driver and starts fixed; alter observations or the plant. Delayed inputs are genuinely old observations. Noise affects lane, heading and speed sensors; ideal previews remain unchanged. This measures robustness to a shift the model never trained for; it does not make the model robust.

Grip scales the lateral-acceleration limit and available braking. It is a hard threshold, not tyre slip, so failures are abrupt. The policy does not receive a grip measurement. Random streams are reproducible within each runtime, but browser RNG is not NumPy's RNG.
